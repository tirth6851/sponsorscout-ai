# SponsorScout AI

A visa-aware career navigator for international students. Matches students to job opportunities based on sponsorship history, CPT/OPT/H-1B compatibility, skills, and location preference — with a deterministic match scoring engine and a Groq-powered AI strategy layer.

---

## What It Does

- **Visa-aware matching** — scores each opportunity against the student's visa status, sponsorship need, CPT/OPT compatibility, and STEM eligibility
- **Groq AI strategy** — calls `llama-3.3-70b-versatile` via Groq API to generate personalised career plans; deterministic fallback if Groq is unconfigured
- **Demo mode** — works fully without Supabase or Groq credentials; mock data with live scoring is used as a fallback
- **Auth + data isolation** — Supabase Auth (email/password) with Row Level Security policies ensuring each user sees only their own data

## Match Scoring Algorithm

Located in `lib/matching.ts`. Pure TypeScript, no external calls.

| Category | Points | Logic |
|---|---|---|
| Authorization compatibility | 35 | CPT/OPT support (+20), H-1B sponsor when needed (+15), incompatible = hard penalty |
| Sponsorship history | 20 | Strong History=20, Occasional=10, Rare=3 |
| Skills overlap | 25 | Fuzzy substring match ratio × 25 |
| Location / remote | 12 | Exact city or remote=12, same state=6 |
| Industry alignment | 8 | Exact industry match |
| Experience level | 5 | Exact match bonus; penalty for 2+ levels above student |

**Fit tiers**: Realistic ≥ 75 · Stretch ≥ 50 · Low-Fit < 50

## Strategy Generation

When `GROQ_API_KEY` is set, `/api/strategy` calls Groq (`llama-3.3-70b-versatile`) with the student's profile and top matches to generate a personalised strategy. The UI badge says "Generated by Groq AI". If Groq is not configured or fails, the deterministic fallback runs from `lib/strategy.ts` (no API calls) and the badge says "Algorithmic Strategy".

## Environment Variables

### Local development

Create `.env.local` in the project root:

```bash
# Supabase — required for auth + real data; omit to use demo mode
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...

# Supabase service role — server-only, never expose to client
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...

# Groq — server-only, never expose to client
GROQ_API_KEY=gsk_...
GROQ_MODEL=llama-3.3-70b-versatile

# App URL
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

**Demo mode**: If `NEXT_PUBLIC_SUPABASE_URL` is missing or does not start with `https://`, the app runs in full demo mode — all pages work with mock data scored by the real algorithm.

### Vercel deployment

In your Vercel project, go to **Settings → Environment Variables** and add each variable for both **Production** and **Preview** environments:

| Variable | Where to find it |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Dashboard → Project Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase Dashboard → Project Settings → API → Project API Keys → `publishable` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Dashboard → Project Settings → API → Project API Keys → `service_role` (keep secret) |
| `GROQ_API_KEY` | [console.groq.com](https://console.groq.com) → API Keys |
| `GROQ_MODEL` | Set to `llama-3.3-70b-versatile` |
| `NEXT_PUBLIC_APP_URL` | Your Vercel deployment URL, e.g. `https://sponsorscout.vercel.app` |

> **Important**: `GROQ_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` must NOT be prefixed with `NEXT_PUBLIC_`. They are server-only and are never sent to the browser.

## Troubleshooting

### `Invalid API Key` on Vercel deployment
- **Most common cause**: `GROQ_API_KEY` was pasted with extra spaces. Go to Vercel → Settings → Environment Variables, delete and re-add the key making sure there are no leading/trailing spaces.
- Also check `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — it should start with `sb_publishable_`.

### Wrong Supabase URL
- `NEXT_PUBLIC_SUPABASE_URL` must start with `https://` and end with `.supabase.co`.
- Find it in Supabase Dashboard → Project Settings → API → Project URL.
- If the URL is missing or wrong, the app runs in demo mode (this is intentional).

### Using `NEXT_PUBLIC_SUPABASE_ANON_KEY` instead of `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- Both are accepted as a fallback. The newer `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` is preferred. If you only have the old anon key (JWT format starting with `eyJ`), set it as `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in Vercel.

### Build fails with "Invalid API Key" locally
- Check `.env.local` — make sure `GROQ_API_KEY` has no spaces and `NEXT_PUBLIC_SUPABASE_URL` starts with `https://`.
- Run `npm run build` — all API routes have `export const dynamic = 'force-dynamic'` so no external calls are made during the build.

### `NEXT_PUBLIC_SUPABASE_ANON_KEY` vs `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- Supabase renamed "anon key" to "publishable key" in 2025. Both names are accepted by this app. Use whichever your Supabase Dashboard shows.

### Tables

| Table | Purpose |
|---|---|
| `profiles` | Thin auth-linked row; auto-created on signup via trigger |
| `student_profiles` | All form data: visa, degree, skills, career goals |
| `opportunities` | Job listings with USCIS H-1B sponsorship data |
| `saved_opportunities` | Per-user bookmarks with cached match scores |
| `strategy_outputs` | Generated strategy JSON per user |
| `action_items` | Per-user action plan items with completion state |

All tables have Row Level Security enabled. Users can only read and write their own rows. Opportunities are readable by all authenticated users.
